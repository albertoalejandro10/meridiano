# BetoTracker Setup Guide

BetoTracker runs on **NuxtHub** with a **PostgreSQL** database (via Drizzle ORM) and **email/password auth** (nuxt-auth-utils). This guide covers local development and deployment.

## Local Development

```bash
cp .env.example .env             # local-dev defaults
docker compose up -d postgres    # Postgres 18 on localhost:5433
pnpm install
npx nuxt db migrate              # apply migrations (also auto-applies on `nuxt dev`)
pnpm dev                         # http://localhost:3000
```

### `.env` for local development

```dotenv
# Sealed-cookie session secret (>=32 chars in prod; auto-generated in dev if unset)
NUXT_SESSION_PASSWORD=change-me-to-a-random-32-char-string

# NuxtHub Database connection (Drizzle / postgres-js)
DATABASE_URL="postgresql://beto_tracker:beto_tracker_password@localhost:5433/beto_tracker"
```

Notes:

- The local DB runs on host port **5433** (5432 is often taken by other projects).
- NuxtHub reads the Postgres connection from `DATABASE_URL` (`POSTGRES_URL` / `POSTGRESQL_URL` also work).
- Without a session, `/app` pages redirect to `/login` and `/api/v1/*` correctly returns **401**.

### Database workflow (Drizzle + NuxtHub)

- Schema lives in `server/db/schema.ts` (Drizzle, `pg-core`).
- After changing the schema: `npx nuxt db generate` writes a migration to `server/db/migrations/postgresql/` (commit it).
- Apply migrations: `npx nuxt db migrate` (or just run `pnpm dev` — migrations auto-apply in dev).
- `drizzle.config.ts` is generated by NuxtHub under `.nuxt/hub/db/` — **do not** create or edit it by hand.

### Auth model

Email/password is handled entirely in-app by nuxt-auth-utils:

- `POST /api/auth/register` — creates the user (hashed password) and starts a session
- `POST /api/auth/login` — verifies the password and starts a session
- `POST /api/auth/logout` — clears the session
- The session is a signed/sealed cookie (`nuxt-session`); `server/middleware/auth.ts` reads it and sets `event.context.userId` for `/api/v1/*`.

> Browsers treat `http://localhost` as a secure context, so the `Secure` session cookie works in local dev. (Plain `curl` over HTTP won't send a `Secure` cookie unless you pass it manually.)

## Run & smoke-test the app

```bash
pnpm dev
```

1. Visit `http://localhost:3000` → **Get started** → `/signup`
2. Create an account (name + email + password) → you're redirected to `/app`
3. Create an account and a transaction → balances update
4. Sign out (sidebar footer) and sign back in via `/login`

Verify unauthenticated API access is rejected:

```bash
curl -i http://localhost:3000/api/v1/accounts   # 401 Unauthorized
```

## Deployment

1. Provision a managed PostgreSQL (Neon, Supabase pooler, a Hyperdrive-backed Postgres, etc.).
2. Set production environment variables:
   - `DATABASE_URL` — the managed Postgres connection string
   - `NUXT_SESSION_PASSWORD` — a strong 32+ character secret
3. Apply migrations against the production DB: `npx nuxt db migrate`.
4. Build & run. `pnpm build` does **not** need a database (`hub.db.applyMigrationsDuringBuild` is off). The Docker image (`Dockerfile`) builds the Nitro server; run it with `--env-file .env`.

NuxtHub can also deploy to Cloudflare — see the [NuxtHub docs](https://hub.nuxt.com/docs). When deploying to Workers, front the Postgres connection with Hyperdrive (or use a serverless Postgres driver).

## Troubleshooting

**`getaddrinfo ENOTFOUND <host>` on `nuxt db migrate`** — `DATABASE_URL` points at an unreachable host. For local dev, use the Docker Postgres string (`...@localhost:5433/...`).

**`relation "..." does not exist` / empty database** — Run `npx nuxt db migrate`. If the DB has stale tables from a previous tool, reset it (local only): `docker exec beto-tracker-postgres psql -U beto_tracker -d beto_tracker -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"` then migrate again.

**`postgres-js driver requires DATABASE_URL ...` at build time** — Only happens if `applyMigrationsDuringBuild` is enabled. It's disabled in `nuxt.config.ts`; keep it off for CI/Docker builds, and run `nuxt db migrate` at deploy instead.

**API returns 401 in the browser after login** — Ensure `NUXT_SESSION_PASSWORD` is set and stable (changing it invalidates existing sessions).

## Post-MVP: Blob Storage

NuxtHub Blob will back two planned features (not in the MVP): **transaction receipt attachments** and **user avatars**. The database already reserves the columns (`transactions.receiptPathname`, `users.avatarPathname`, both nullable), so shipping the feature is additive.

To enable it later:

1. Turn on blob in `nuxt.config.ts` (`hub.blob: true`, alongside the existing `hub.db`), and configure the binding/driver per the NuxtHub Blob docs.
2. Add the endpoints (sketch):
   - `POST /api/v1/transactions/:id/receipt` → `hubBlob().put(...)`, store the returned pathname in `transactions.receiptPathname` (ownership-checked).
   - `POST /api/v1/me/avatar` → `hubBlob().put(...)`, store in `users.avatarPathname`.
   - `GET /api/v1/blob/[...pathname]` → `hubBlob().serve(event, pathname)` (ownership-checked).
3. Wire the UI (receipt upload in the transaction modal; avatar upload in the user menu) and surface `avatarPathname` on the session if you want it in `useUserSession()`.

See the [NuxtHub Blob docs](https://hub.nuxt.com/docs/features/blob) for `hubBlob()` usage.
